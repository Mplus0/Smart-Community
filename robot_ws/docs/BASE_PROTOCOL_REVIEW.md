# 底盘通信协议对比

## 最终结论

恢复正确USB连接和绑定后，当前程序正常接收底盘反馈并完成架空前进/停止测试。
此前无反馈不是当前解析代码独有的现象；详见 [验收记录](ACCEPTANCE.md)。

## 旧入口与来源

/home/mowen/start_robot.sh 启动 bit_ws 的 car_sim/nav_real.launch，
其中底盘发送为 car_bringup/scripts/newt.py，接收为 pubv.py。
control_ws 主要提供任务、识别、播报和录像。
旧目录另有115200或9600波特率的0x11版本，但不是该启动脚本选择的发送入口。

## AA BB 实现核对

| 项目 | 旧程序 | 当前serial_bridge.py |
|---|---|---|
| 串口 | newt.py用ttyUSB0，pubv.py用carserial | 统一使用carserial |
| 波特率 | 115200 | 115200 |
| 初始化 | 11加8个00，字节间隔1ms | 相同 |
| 发送 | AA BB 0A 12 02 + 小端三轴int16 + 00 | 相同 |
| 速度比例 | x/y/yaw乘1000 | 相同 |
| 反馈帧 | AA BB开头，12字节，速度在字节4–9 | 相同 |
| 校验 | 字节2–9求和取低8位，与字节11比较 | 相同 |
| yaw比例 | 0.95 | 默认0.95 |
| 读取方式 | read(12)，超时5秒 | read(64)，超时0.05秒，缓冲重同步 |
| 负值转换 | 手工转换有1计数偏差 | 标准有符号int16 |
| 串口访问 | 两个进程打开同一端口 | 单进程负责读写 |

提取旧callback和当前encode_velocity，在内存截获输出：
零速、正向、负横移、负转向、混合三轴共5组，输出字节完全一致。
该对比中的非零值未发送给实车。
旧接收器没有发送反馈使能或轮询命令；旧发送器除初始化与速度命令外无额外握手。
当前协议内容未因本轮排查修改。
