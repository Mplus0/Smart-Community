## 2. 本机 P1：启动裁判系统

在 **Windows PowerShell** 执行，保持该窗口运行：

```powershell
Set-Location 'D:\Desktop\智慧社区\裁判系统\离线部署包'
$env:PORT = '8080'
$env:PYTHONUTF8 = '1'
& '.\.venv\Scripts\python.exe' 'app.py'
```

本机浏览器打开：

```text
http://127.0.0.1:8080/
```

如果页面已经能打开，说明已有服务，无需重复启动。检查监听进程可另开一个 **本机 PowerShell**：

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
```

确认本机 192.168.31.x 地址：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.31.*' } | Select-Object InterfaceAlias, IPAddress
```

只有在小车无法连接 8080 时，才在**管理员 PowerShell** 中检查并添加入站规则：

```powershell
if (-not (Get-NetFirewallRule -Name 'CommunityJudge8080' -ErrorAction SilentlyContinue)) {
    New-NetFirewallRule -Name 'CommunityJudge8080' -DisplayName 'Community Judge TCP 8080' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -Profile Any
}
```

## 4. 小车 S1：启动底盘、相机、定位导航和识别服务

完成第 3 节环境加载后，在 **小车 S1** 执行：

```bash
roslaunch community_bringup community.launch base_protocol:=aa_bb local_planner:=teb run_mission:=false
```

该命令启动底盘串口、雷达、IMU、主相机、UGREEN 仪表相机、定位与 TEB 导航、检测模型、OCR、测温、录像等基础服务。`run_mission:=false` 表示暂不执行巡检路线；等你在 S2 发出测试命令。

保持 S1 运行，等待相机和识别模型完成加载。这里明确使用 `local_planner:=teb`，沿用小车现有 TEB 配置。

**已有基础系统运行时不重复启动。** 本流程不同时运行 `hardware.launch`、`navigation.launch`、`services.launch` 或 `finals.launch`，避免重复节点或提前开始完整巡检。

## 10. 大屏没结果时按这个顺序查

| 现象 | 检查或处理 |
|---|---|
| 小车 `curl` 超时/拒绝连接 | 笔记本裁判进程是否运行、IP 是否为 192.168.31.83、TCP 8080 是否放行 |
| `/api/hello` 返回 403 | 裁判页面是否锁定其他队伍；先核对队名，再通过大屏解除锁定或切换队伍 |
| 任务结束但没有上传 | 是否加了 `judge_enabled:=true`，是否误用了 `navigation_only:=true`；查看 S2 上报日志 |
| 相机超时或始终看不到目标 | 人员等点可能用 UGREEN，按下一节表确认，不要只检查 Orbbec |
| 仪表任务 SKIPPED | 查看三项读数、取景和 OCR；跳过任务不会上传成功结果 |
| 红绿灯/障碍判断在大屏找不到 | 这两种任务不上传，查看 S2 或结果 JSON |
| 服务不存在/模型未就绪 | 等待 S1 加载；用第 5 节 `rosservice list` 检查对应服务 |
| 新一轮仍看见旧识别结果 | 大屏会保留先前上报；查看实时流水和最新图片，避免把旧数据当作本轮结果 |

调试时不要运行裁判包内的“现场自检”来判断真实识别结果：它会发送模拟数据并重置当前大屏。若要清空之前的调试结果，确认当前没有测试运行后再在大屏上手动重置。

## 12. 停止与最短操作顺序

正常调试结束：先在 **S2** 按 Ctrl+C 停止当前任务，再在 **S1** 按 Ctrl+C 停止基础系统，最后在 **P1** 按 Ctrl+C 关闭裁判服务。只关闭浏览器不会停止裁判系统。

若导航运动中需要中止，先停止 S2 当前任务；必要时取消 move_base 的目标（**小车 S3**，已加载环境）：

```bash
rostopic pub -1 /move_base/cancel actionlib_msgs/GoalID '{}'
```

停止其他速度发布节点后，可发送一次零速度：

```bash
rostopic pub -1 /cmd_vel geometry_msgs/Twist '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

持续存在的运动指令可能覆盖单次零速度，现场异常时使用小车实际急停。`task_only` 不会主动取消其他节点的导航或运动。

**最常用的一轮调试：**

1. 本机 P1 启动裁判系统，浏览器打开大屏。
2. 小车 S1 SSH、加载环境，启动 `community.launch ... run_mission:=false`。
3. 小车 S2 SSH、加载环境；需要移动时先运行第 6 节单点导航。
4. 停稳后，在同一个 S2 执行第 7 节相应 `task_only` 单任务命令。
5. 在本机裁判大屏看结果和图片；S1 无需为每次测试重启。

本文核对了小车实际启动文件、航点与参数；文档整理过程未执行导航或识别测试命令。
