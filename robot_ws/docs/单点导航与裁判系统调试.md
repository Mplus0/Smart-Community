# 30 分钟现场正式运行操作单

更新：2026-11-27。用于提前完成系统测试后的现场运行，按当前本地主路线整理。

## 时间安排

| 时间 | 操作 |
|---|---|
| 0～5 分钟 | 启动裁判与基础系统，小车摆回起点，确认实际位置、朝向与 RViz 定位一致 |
| 5～25 分钟 | 启动一轮完整巡检，观察小车与裁判大屏 |
| 25～30 分钟 | 确认任务结束和上报结果，保留本轮记录，停止系统 |

这是现场时间分配，不代表已经验证整条路线能在 20 分钟内完成。基础系统和裁判已运行时直接复用。

## 1. Windows：裁判系统

本机 PowerShell（已启动则跳过）：

```powershell
Set-Location 'D:\Desktop\智慧社区\裁判系统\离线部署包'
$env:PORT = '8080'
$env:PYTHONUTF8 = '1'
& '.\.venv\Scripts\python.exe' 'app.py'
```

浏览器打开 [裁判大屏](http://127.0.0.1:8080/)，保持裁判窗口运行。

本文使用小车 `192.168.31.59`、裁判电脑 `192.168.31.83:8080`、队名 `麦当劳薯条三重奏`。现场地址以提前测试确认的值为准；使用现场提供的裁判服务时，将下方 `judge_url` 换为该服务地址。

## 2. 小车终端 S1、S2：连接并加载环境

打开两个本机终端，各执行：

```powershell
ssh mowen
```

连接后，每个终端各执行一次以下 Bash 命令：

```bash
source /opt/ros/noetic/setup.bash
source /home/mowen/cartographer_ws/install_isolated/setup.bash
cd /home/mowen/workspace/Smart-Community/robot_ws
source devel/setup.bash --extend
unset ROS_HOSTNAME
export ROS_MASTER_URI=http://192.168.31.59:11311
export ROS_IP=192.168.31.59
```

## 3. S1：启动基础系统

```bash
roslaunch community_bringup community.launch base_protocol:=aa_bb local_planner:=teb run_mission:=false
```

保持 S1 运行。等模型和相机完成加载，将小车摆到已验收的起点；在已有 RViz 中确认位置和朝向，需要时用 `2D Pose Estimate` 校正。确认完成后再执行下一步。

## 4. S2：正式开始完整巡检

```bash
roslaunch community_mission mission.launch judge_enabled:=true judge_url:=http://192.168.31.83:8080 judge_team:=麦当劳薯条三重奏
```

这一条命令完成整轮导航、识别和上报。保持 S1、S2 与裁判系统运行，观察小车运动和大屏实时流水、最新图片。

| 运行阶段 | 现场观察 |
|---|---|
| 红绿灯 | 到点等待，连续有效绿灯后继续；超时会终止 |
| wp_05 指示牌与选路 | 识别禁止直行标志，播报并上传带框图片，自动选择直行或绕行分支 |
| 人员、火情 | 大屏出现对应识别结果和图片；人数按本轮已执行点汇总，火情包含楼名和隐患数量 |
| wp_08 / blocked_wp_22 | 调用红外测温，上报异常楼层与同帧热像框选图；有异常时语音播报 |
| wp_11 / blocked_wp_25 | 使用 UGREEN 读取温度、湿度与电量，上传指针图及电表数字、单位框选图；20 秒内未获得有效读数则跳过，不上传成功结果 |
| wp_27、wp_28、wp_31 | 分别上报 1、2、3 号车牌及车牌定位框图片 |
| wp_29 | 上报垃圾桶及投放判定 |
| wp_35 停车区 | 停车等待 0.8 秒后拍照，统计正常、倒伏及总数量；上报电动车结果与标注图 |
| 收尾 | wp_35 后直接前往 wp_37，最终在 wp_39 结束 |

两个分支都已启用仪表识读、楼宇测温、2 个红绿灯和 3 个火情识别点；普通图像任务按航点自动选择主相机或 UGREEN。指示牌识别结果会播报并显示在大屏“标志”任务；其他常规识别结果尚未接入语音。红绿灯结果看 S2 终端，不上传大屏。30 分钟为调试窗口，正式比赛每轮按本地规则为 5 分钟，目前程序没有全程 300 秒截止控制。

## 5. 本轮结束：确认并保留结果

在 S2 确认 `[巡检结束] 状态=FINISH`；在裁判大屏确认本轮流水及图片。`FINISH` 表示巡检结束，上报是否成功还要看 `[裁判上报成功]` 和大屏。

本轮目录以 S2 打印的 `[输出目录]` 为准，包含：

- `mission_results.json`：本轮任务结果。
- `mission.log`：本轮运行日志。
- `judge_reports.jsonl`：上报记录，`sent` 表示接口接收成功，`failed` 记录失败原因。
- `photo/`：原图及识别标注图。

正常结束后，若 S2 尚未退出先按 Ctrl+C，再在 S1 按 Ctrl+C，最后关闭自行启动的裁判进程。

## 异常中止

需要立即制动时使用小车实际急停。先在 S2 按 Ctrl+C 停止巡检；在已加载环境的空闲小车终端取消导航目标：

```bash
rostopic pub -1 /move_base/cancel actionlib_msgs/GoalID '{}'
```

停止其他运动控制程序后发送零速度：

```bash
rostopic pub -1 /cmd_vel geometry_msgs/Twist '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

确认小车停稳后再处理异常。重新执行第 4 步会从路线起点开始新一轮，不能从中断点自动续跑；重新运行前先恢复起点位置和定位。
