# 三种识别结果接口

三个节点默认订阅 `/camera/color/image_raw`（sensor_msgs/Image），支持rgb8/bgr8/mono8/rgba8/bgra8和行padding。默认每路最多处理5帧/秒，仅处理最新帧；实际频率取决于算力。输出图为bgr8 Image并保留输入Header，JSON封装在std_msgs/String.data中。

| 功能 | 图像话题 | JSON话题 |
| --- | --- | --- |
| 人物 | /perception/person_image | /perception/person_detections_json |
| 车牌 | /perception/plates_image | /perception/plates_json |
| 交通灯 | /perception/traffic_light_image | /perception/traffic_light_json |

## 人物

JSON含header、width/height、frame_valid/reason、processing_ms和detections数组。每个框含class_id、label、display_label、confidence和bbox_xyxy。0=community_person（C），1=non_community_person（NC）。有效无人帧输出空数组；断流状态frame_valid=false/reason=camera_stale，推理/解码异常另有原因。像素框均为原图[x1,y1,x2,y2]。

## 车牌

JSON含schema_version=1、engine=hyperlpr3、header、width/height、inference_ms、processing_ms和plates数组。每个车牌含text（完整中文/字母/数字车牌号）、confidence、plate_type_id、bbox_xyxy。没有车牌的成功处理帧输出plates=[]；阈值默认0.5。plate_type_id是HyperLPR3类型编号，业务需要解释时按该库版本定义核对。

注意现有车牌JSON没有frame_valid/reason。相机断流、帧陈旧或处理异常时不再发布结果，不会补发错误JSON。消费方必须设置接收超时，同时检查源stamp，不能无限复用上次识别号码。中文字体缺失只影响预览图文字（退化成plate#编号），JSON仍保留号码。

## 交通灯

JSON含header、width/height、frame_valid/reason、processing_ms与traffic_lights数组。每组含bbox、lamps颜色/亮度统计、raw_state、state、valid、track_id、规则score等。state为RED/YELLOW/GREEN/UNKNOWN；无灯为数组为空，不能解释成绿灯；歧义时valid=false。GREEN需同一临时图像轨迹连续3个新帧确认，RED/YELLOW即时报告；重复/倒退时间戳、断流会清除确认。画面只显示颜色名，完整诊断字段在JSON；score是规则评分，不是概率或准确率。

## 主功能包接入

用json.loads(msg.data)解析每一路String。三路独立异步处理同一输入话题，没有统一JSON/同帧融合图；不能假定最后收到的三条消息来自同一帧。分别检查消息有效性/新鲜度，再由主功能包关联任务与场景。

人物没有永久ID和街区位置，不能把每帧框数直接累加为人数。灯track_id是短期图像关联号，不是世界灯位ID；车牌没有停车位归属。三个识别节点均不发布cmd_vel，红灯停车、街区去重、目标选择和巡检调度由M/C协调实现。
